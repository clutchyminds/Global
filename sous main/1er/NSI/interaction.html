📚 Cours complet – Interactions homme-machine & Web

L'interaction homme-machine (IHM) désigne l'ensemble des moyens de communication entre une personne et une machine : écrans, claviers, souris, boutons, commandes vocales, formulaires, etc.

Interface Exemple Utilité Ergonomie ?
Graphique (GUI) Boutons, menus, pages web Navigation simple, interactive Oui, prioritaire (UX/UI design)
Ligne de commande Terminal, shell Commandes textes puissantes Moins ergonomique/bruit d’apprentissage
Sensorielle Vocale, tactile, gestuelle Accessibilité, contexte mobile Oui (mais nécessite IA ou capteurs)
Web (HTML/CSS/JS) Formulaires, chats, articles, dashboards Universalité, transversalité devices Variable selon le design et l’accessibilité

Éléments essentiels :

  • Des entrées/sorties : clavier, souris, champs textes, boutons, pavés tactiles, commandes vocales
  • L’ergonomie : intuitive, rapide, accessible, agréable
  • L’accessibilité : utilisable par tous (règles ARIA), contraste, synthèse vocale
  • La rétroaction : la machine répond à l’action humaine (message d’erreur, succès, surbrillance…)
  • Sur le web : HTML (structure), CSS (apparence), JavaScript (interactions dynamiques, formulaires, menus)
  • Bonnes pratiques : Toujours expliquer, prévoir les erreurs de saisie, rendre attractif !
Exemples sur le web :
  • Formulaire d’inscription, recherche Google, bouton “Envoyer”
  • Menus déroulants, icônes cliquables, liens hypertextes
  • Captchas, notifications, fenêtres modales (pop-ups)
  • Responsive design : s’adapte à la taille de l’écran
Objectif NSI : Analyser, critiquer et imaginer de meilleures interfaces pour tous.

📋 Fiche synthèse interactive

  • À quoi sert l’ergonomie dans une interface ? Rendre l’utilisation rapide, confortable, sans erreur. On pense à tous (jeunes, seniors, oeil daltonien, etc.)
  • Quel langage rend une page web interactive ? JavaScript, pour valider un formulaire, afficher des popups, animer, etc.
  • Accessibilité, à quoi ça sert ? Permettre à TOUS d’utiliser l’interface, même avec un handicap (malvoyant, moteur…).
  • Trouve un exemple de rétroaction sur le web : Message de validation, d’erreur, changement de couleur d’un bouton, “popup”.
  • Défi : À quoi sert le responsive design sur mobile/web ? Adapter l’affichage automatique à la taille de l’écran (téléphone, tablette, PC).

💡 Exercices interactifs

Si tu devais améliorer un formulaire web : que ferais-tu ?

Ajouter labels explicites, message d’erreur clair, grands boutons, contraste couleurs, validation instantanée.

Dans quelle situation l’accessibilité web est-elle essentielle ?

Pour les personnes malvoyantes (lecteur d’écran), personnes âgées, ou toute situation où l’utilisateur a des besoins particuliers.

🎯 Quiz rapide

Quel langage n’est pas utilisé pour l’interface web ?

Comment appelle-t-on l’expérience vécue par l’utilisateur ?

🌍 Applications concrètes

  • Formulaires d’inscription, chat, applis mobiles, systèmes embarqués (voiture, avion, domotique…)
  • Jeux vidéo : menus, HUD, interaction touch ou manette
  • Administrations, hôpitaux, transports : bornes, systèmes d’alerte, terminaux de paiement
  • Tout le Web : chaque site, chaque bouton, animation ou retour visuel…

❌ Erreurs fréquentes à éviter

  • Utiliser un texte ou bouton trop petit, pas accessible
  • Oublier de tester l’interface sur mobile et tablette
  • Ne pas montrer d’erreur ou de réussite à l’utilisateur
  • Laisser un champ sans label ou explication
  • Ignorer le contraste, la couleur, ou les handicaps

📚 Lexique express

IHM / HMI : Interface Homme-Machine
UI : User Interface (ce que l’on voit)
UX : User Experience (“ressenti” de l’utilisateur)
Accessibilité : capacité d’usage universel (handicap, langue)
Formulaire : zone de saisie de données (web)
Responsive : adaptation à l’écran

📖 Anecdotes et histoire

  • Le premier “smiley” “:-)” a été utilisé par Scott Fahlman en 1982 dans une interface de forum !
  • L’IHM graphique (GUI) date de Xerox Parc, popularisé par Apple Lisa/Mac et Windows (années 80).
  • L’accessibilité web (normes WAI-ARIA) est devenue obligatoire pour les sites publics français depuis 2005.
  • Un clic mal placé peut générer des millions d’euros de pertes (vente ratée, bug, incompréhension…) !
Source : NSI, histoire du web, UX/UI
Astuces mémoire : “UI” = “tu vois”; “UX” = “tu ressens”; “Responsive” ↔ “répond” à la taille écran.

💡 Méthodologie contrôle

  • Analyser une interface : repérer forces/faiblesses (lisibilité, boutons, labels, responsive…)
  • Être capable de proposer au moins 2 améliorations
  • Savoir citer les langages/technos du web (HTML, CSS, JS)
  • Prévoir la rétroaction (erreur/succès…) et l’accessibilité
  • Justifier chaque choix par l’expérience utilisateur (UX)
